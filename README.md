# ExhibitFlow Studio

ExhibitFlow Studio is an offline-first React workspace for museum exhibition teams. Curators can shape an object collection, designers can build a visitor journey, reviewers can close findings, and the team can compare visitor scenarios before exporting a readiness snapshot.

## Run locally

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:4173`. The app uses the browser's local storage key `exhibit-flow.workspace.v1`; no network services or environment variables are required. Use **Reset sample plan** in the sidebar to restore the built-in exhibition.

## Validation commands

```bash
npm run build       # TypeScript and Vite production build
npm run test        # Vitest unit tests
npm run test:e2e    # Playwright browser workflows
npm run check       # all checks in sequence
```

## Directory structure

- `src/domain`: entities, validation boundaries, journey analysis, state transitions, readiness, and scenario projection.
- `src/state`: reducer commands, selectors, seed data, and local persistence.
- `src/features/collection`: searchable object library and validated editor.
- `src/features/journey`: sequenced zone lanes, placement commands, and constraint feedback.
- `src/features/review`: finding lifecycle, readiness gate, and snapshot export.
- `src/features/insights`: non-mutating visitor scenario controls and derived metrics.
- `src/components`: shared shell, navigation, forms, badges, metrics, dialogs, and visual primitives.

## Inputs and outputs

- Object records accept accession ID, title, maker, period, medium, origin, dimensions, dwell time, narrative role, sensitivity, access need, tags, and key-object status.
- Review findings accept severity, owner, optional zone/object links, and decision context.
- A successful readiness check enables a JSON file named `exhibit-flow-snapshot-YYYY-MM-DD.json` containing the project, sequenced zones, objects, summary metrics, unresolved non-blocking issues, and a `lineage` block with the full reference closure (every dependency, its import source, and any needs-review/deleted-source state).
- **Import:** the Collection page accepts an `Import file` JSON document of the shape `{ "artifacts": [ { "accessionId", "title", "maker", "medium", "summary", "width", "height", "depth", "dwellMinutes", "narrativeRole", ... } ] }`. Each import is a persisted batch provenanced by a content hash; re-importing the identical file never duplicates records or relationships.
- **Backup / restore:** the sidebar **Backup** button writes `exhibit-flow-backup-YYYY-MM-DD.json`, a full workspace export that includes the provenance graph. **Restore** reads it back, preserving every source, stale flag, and published-package dependency.

## Planning lineage

Provenance is a persisted graph inside the workspace state (`lineage.nodes`, `lineage.edges`, `lineage.batches`):

- Nodes represent objects, placements, findings, import batches, and published packages; edges record *assigned*, *linked*, *generated by import*, and *exported* relationships.
- Object records carry a content signature. Editing an object's content flags every downstream placement/finding/package as **needs re-review** (`source-modified`) instead of showing them as fully valid. Deleting an object tombstones its placement and flags findings and already-published packages (`source-deleted`); removing a placement flags `source-removed`.
- Detail views (object, placement, finding) show direct sources, the full transitive source closure, downstream dependents, and import batch. A reviewer can mark a flagged record as reviewed.
- Deleting an object opens an impact dialog listing affected placements, findings, and published packages.
- Workspaces created before lineage are backfilled automatically; the graph is included in backups and survives restore. All graph ids are deterministic, so reconciliation and identical-file imports are idempotent.

## Design notes

State-changing feature actions call typed workspace commands. Commands validate at the boundary, dispatch reducer events, and persist the complete workspace. Derived analysis is pure and can be recalculated for scenario projections without changing the saved plan.
